# ToonStyle Pixal3D Pipeline Spec

Phase: 1C R2 / FinalFoundationPass

This document is the text source of truth for the Pixal3D -> Blender -> Unreal
production pipeline. `MaterialSpec.md` owns material asset structure; this file
owns generation settings, Blender processing order, importer binding policy, and
reporting/verifier contracts.

## Pixal3D Request Defaults

Strict production defaults:

- Resolution: `1536`.
- Texture size: `4096`.
- Decimation: `200000`.
- Fallback decimation: `80000`, diagnostic mode only.
- Remesh: `true`; `false` only for per-asset accepted limitations such as Loot
  Chest or Loot Crate no-remesh paths.
- Sampling: `ss_steps=25`, `ss_guidance=7.5`, `shape_steps=25`,
  `shape_guidance=7.5`, `tex_steps=25`, `tex_guidance=4.0`.
- Fallback policy: `export_fallback=false` and
  `safe_fill_holes_fallback=false` in strict production. `--diagnostic-mode`
  can allow fallback so operators can inspect what would fail, but fallback
  responses remain verifier failures unless the manifest marks that specific
  asset as an accepted limitation.

## Height Normalization Policy

- Default normalization height: `180.0` Unreal units.
- Height is manifest-driven per asset. If no override is provided,
  `run_toon_pipeline.py` uses the `--target-height` default.
- Asset class does not implicitly set height. `humanoid`, `creature`, `prop`,
  and `accepted-limitation` drive normal handling and validation thresholds, not
  scale.
- Older `2.0 m` references belong to the QuadRetro character pipeline, not the
  Pixal3D ToonStyle production pipeline.

Code references:

- Pipeline default: `ToonStyle/BlenderScripts/run_toon_pipeline.py:52`.
- Wrapper manifest fallback default:
  `Model Generation/Pixal3D/Scripts/run_pixal3d_toonstyle_production_import.py:61-64`.

## Blender Processing Order

Canonical order in `ToonStyle/BlenderScripts/run_toon_pipeline.py`:

1. Import Pixal3D GLB: `run_toon_pipeline.py:419`.
2. Extract source textures: `run_toon_pipeline.py:425-427`.
3. Join source meshes into one shading mesh: `run_toon_pipeline.py:429`.
4. Normalize height from manifest/default target height: `run_toon_pipeline.py:430`.
5. Dump UV triangle data for texture post-processing: `run_toon_pipeline.py:431`.
6. K-means flatten diffuse textures: `run_toon_pipeline.py:436-444`.
7. Texture post-processing: palette snap, speckle cleanup, UV padding, and Tint
   generation: `run_toon_pipeline.py:348-358` and
   `ToonStyle/BlenderScripts/texture_postprocess.py:263-299`.
8. Strip material texture references: `run_toon_pipeline.py:445`.
9. Author vertex colors on `Col` (`CORNER`, `BYTE_COLOR`) from Cycles AO:
   `run_toon_pipeline.py:446` and
   `ToonStyle/BlenderScripts/author_vertex_colors.py:19-80`.
10. Run generic shading-normal editing on non-humanoids only; humanoids are
    explicitly skipped to preserve face-normal transfer:
    `run_toon_pipeline.py:151-178` and `run_toon_pipeline.py:447`.
11. Duplicate the shading mesh into the outline mesh:
    `run_toon_pipeline.py:449`.
12. Reverse outline winding while preserving captured outward vertex normals as
    custom split normals: `run_toon_pipeline.py:450`.
13. Run ToonStyle foundation tools: close-the-gap B-channel curvature authoring
    plus inner-line texture bake: `run_toon_pipeline.py:451-456`.
14. Humanoid face/head normal transfer is deprecated and disabled in production.
    The pipeline records `normal_transfer.enabled=false` and preserves the
    shading mesh's original normals. The old transfer implementation remains
    physically present only behind the explicit
    `--enable-humanoid-face-normal-transfer` flag for a future revisit pass;
    it is not a production or current remediation path.

Important audit note: the Agent 2 settings report described "step 14" as
"Transfer/edit normals for humanoid head/face presentation." In live code that
is the `transfer_face_normals()` call after outline duplication and foundation
authoring. It is not a second independent normal-edit operation.

## Humanoid Normal Handling

Active humanoid production step:

- Humanoid face/head normal transfer is off. `run_toon_pipeline.py` writes
  `normal_transfer.enabled=false`, `method=disabled_original_normals`, and
  `reason=humanoid_face_normal_transfer_deprecated_disabled_by_default`.
- The production Pixal3D wrapper does not pass
  `--enable-humanoid-face-normal-transfer`; all standard humanoid production
  imports keep the mesh normals generated by the upstream model/Blender import
  path.
- The old density-and-compactness face-mask implementation remains in
  `ToonStyle/BlenderScripts/transfer_face_normals.py` as deprecated code for a
  future research pass. It is not a production requirement and is not validated
  as part of the accepted production import path.
- If the deprecated flag is used in a research branch, the old fail-loud
  threshold still applies:
  if changed loop coverage exceeds 10 percent of total loops, the asset halts
  with `face_mask_overbroad`. The pipeline must not fall back to the old
  top-25-percent behavior.

Deferred R2 humanoid shading-normal extension:

- The generic `shade_smooth` + `WeightedNormal` pass remains non-humanoid-only.
- Humanoids are skipped with
  `skipped_for_humanoid_to_avoid_overwriting_transfer_face_normals`. The string
  is historical; the current production reason is to avoid adding an unreviewed
  humanoid-wide normal edit while the deprecated face-mask path is off.
- Extending that generic pass to humanoids is still deferred until A/B evidence
  proves it improves the no-face-mask production path.

## Texture Pipeline Tunables

Locked defaults:

- `flatten_k = 6`: K-means diffuse cluster count.
- `highlight_cap = 0.85`: diffuse highlight clamp during flattening.
- Speckle cleanup: 3x3 local-median high-contrast pixel replacement with RGB
  distance threshold `42.0`; intentionally conservative.
- Speckle region threshold argument: `8`, passed as the local isolated-region
  size threshold.
- UV padding: `16 px` at 4096 by default; `32 px` for accepted-limitation
  no-remesh assets.
- Tint derivation: HSV value x `0.6`, saturation x `1.1`, hue unchanged.

## Vertex Color Channel Layout

`MaterialSpec.md` owns the locked runtime channel layout:

- R: lighting threshold offset.
- G: outline width multiplier and outline mask (`G=0` means no extrusion).
- B: outline depth offset.
- A: unused in production.

Pipeline ownership:

- R is written from AO during vertex color authoring.
- G is written as outline width/mask support during outline authoring; default
  outline vertices use `G=1` unless explicitly masked.
- B is written from curvature analysis during close-the-gap foundation authoring.
- A is not a production control channel; new code should not depend on it.

## Close-The-Gap Transfer Function

The close-the-gap B channel is curvature-derived:

- Transfer function: percentile clamp plus power response.
- Humanoid and creature assets: percentile bounds `p70` to `p95`, power `0.7`.
  The clamp guarantees roughly 30 percent non-zero B values when curvature has
  enough variation.
- Prop assets: percentile bounds `p65` to `p97`, power `0.7`, yielding roughly
  35 percent non-zero B values.
- Accepted-limitation/no-remesh assets: foundation B authoring is skipped and B
  remains uniform, typically `0`.
- Verifier thresholds: humanoid/creature `B_nonzero_fraction > 0.05`, prop
  `B_nonzero_fraction > 0.01`; all non-accepted assets require `B_max > 0` and
  `B_max <= 1.0`.

## Inner-Line Bake

- Bake resolution matches BaseColor by default: `4096`.
- UV padding follows the same `16/32 px` policy as BaseColor.
- Speckle cleanup is skipped; inner lines are intentionally high-contrast,
  small-pattern mask data.
- Output path: `{asset}_InnerLines.png`.
- Production coverage observed in Agent 2 and prior passes sits around
  `0.082` to `0.21`. Typical anime cel-shading references often run closer to
  `1%` to `5%`, so this remains a downstream visual-tuning lever through the
  bake threshold and material strength.

## Material Binding Policy

- The importer binds only parameters that exist on live
  `/Game/ToonStyle/Materials/M_Toon_Character`.
- Source of truth:
  `ToonStyle/Source/ImportPixal3DAsset_Phase1C.py:_TOON_CHARACTER_PARAMETERS`.
- Current importer-bound texture parameters:
  `BaseColorTexture`, `TintTexture`, `InnerLineTexture`.
- The importer does not bind character scalars or vectors; master defaults own
  those values.
- The outline material still preserves `OutlineColor` on
  `M_Toon_Character_Outline`; outline binding is separate from the character
  material parameter list.
- Future master additions must update `_TOON_CHARACTER_PARAMETERS` only when
  the importer needs to bind them. Future removals are caught by
  `ToonStyle/Source/validate_material_parameter_alignment.py`.

## Report Template Policy

- Agent handoff reports and settings breakdowns must enumerate importer-bound
  material parameters from `_TOON_CHARACTER_PARAMETERS`.
- Static Markdown reports may cite historical values, but reusable generators
  and templates must not hand-list importer parameters.
- Generated reports should include a marker such as:
  `Parameter list: derived at generation time from ImportPixal3DAsset_Phase1C.py:_TOON_CHARACTER_PARAMETERS. Do not hand-edit.`

## Runtime Promotion Boundary

Pixal3D import creates production assets. Gameplay/runtime promotion remains
owned by the specific data table, CSV, C++ default, Blueprint reference, or world
placement system named by the manifest row. Hero and companion character visuals
must be wired through `CharacterVisuals` / hero / companion data, not placed as
static map props.
