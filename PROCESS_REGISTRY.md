# Process Registry

Use this file only after `AGENTS.md` says a task matches a named T66 process area. It is not a startup checklist.

| Process | Trigger | Required process and prohibited substitutions | Verification / reference |
|---|---|---|---|
| Optional Claude/Codex validation | User explicitly asks to validate with Claude/Codex or asks for direct Claude work | Follow `OPTIONAL_VALIDATOR_PROTOCOL.md`. Validation is advisory and per-request unless the user gives a separate explicit instruction. Do not use packet ceremony for ordinary answers. | Validator used, output scope, caveats, and verification performed or skipped. |
| Image generation | New bitmap visuals, mockups, sprites, reference images, or image edits | Use the approved built-in `imagegen` / account-backed image generation path. For repo-bound mockups that would clutter the main chat, use a separate local Codex CLI worker with the same account-backed imagegen process. Close/archive each CLI worker thread after its generation result is collected so it does not remain as open background work. Do not require, revive, or fall back to `OPENAI_API_KEY` API scripts when account-backed imagegen is intended. | Generated image artifact plus visual review; for UI prompts use the self-contained prompt contract under `UI/Reference`. |
| Unreal video and screenshots | Gameplay/UI visual proof, VFX filming, capture requests | Use Unreal-owned capture paths, not desktop screenshots. For VFX/gameplay video use `Scripts/CaptureT66GameplayVideo.ps1`; for UI use `CaptureT66UIScreen.ps1` or `CaptureT66UIWidget.ps1`. Before judging visual proof, check target size, angle, occlusion, temporal sampling, and whether frames prove the stated gate. | Output PNG/MP4 path, frame/log evidence, visibility check result, and ffmpeg/ffprobe check when relevant. |
| Loot UI animation | Loot crate, loot chest, loot bag, loot wheel, or other post-interaction 2D/UI reward animations | Use `PROVEN_PROCESS_FIDELITY.md` plus `UI/Processes/LootUIAnimationAuthoringProcedure.md`. Video references require user-provided transcripts; non-video written references should be read directly. The primary animation carrier must be a target-owned UI surface. | Per-target mechanism packet, artifact parity gate, focused build, Unreal-owned capture, ffprobe/frame evidence, and anti-lookalike discriminator proof. |
| Niagara combat VFX | New combat VFX, slash, aura, projectile trail, elemental attack, or weapon effect | Use `PROVEN_PROCESS_FIDELITY.md` plus Niagara/material/texture workflow: texture masks, material animation, emitters/ribbons/sprites/meshes, timing curves, and reference/source analysis. The primary silhouette must live in the Niagara system, renderer material, renderer mesh/ribbon, or emitter logic. Do not replace with procedural C++ debug geometry, static mesh actor layers, actor-arranged point components, or static lookalike masks unless explicitly approved. | Inspectable Niagara/material assets plus Unreal-owned capture, visual readability review, and multi-frame evidence for temporal mechanisms. Reference `Gameplay/Combat/CombatVFXAuthoringProcedure.md` and `Gameplay/Combat/Hero1AxeVFXPlan.md`. |
| UI reference fidelity | UI screen implementation or edit from a reference image | Follow `UI/Instructions/UI_FIDELITY_LOOP_INSTRUCTIONS.md`. Do not accept "looks roughly right" or compile success without screenshot/dump/fidelity evidence. For FriendslopStyle screens, follow `UI/FriendslopStyle/FRIENDSLOP_STYLE_IMPLEMENTATION_INSTRUCTIONS.md`. | FlatStyle/reference-checklist work uses the owning fidelity checklist and structural report. FriendslopStyle work uses capture/dump/contact evidence, worker records, and the wiring/functionality gate. |
| FriendSlop raw Pixal3D import | Pixal3D asset entering active FriendSlop playable content | Use `Model Generation/Instructions/11_FRIENDSLOP_RAW_PIXAL3D_IMPORT_GUIDELINES.md` for raw static-mesh imports and `Model Generation/Instructions/13_FRIENDSLOP_RAW_HUMANOID_RIGGING_INSTRUCTIONS.md` for physics-first humanoid rigs. Preserve generated GLB base-color texture identity and current material bindings. Archived ToonStyle and QuadRetro docs under `Archive/` are historical only unless explicitly revived. | Manifest/source-run evidence, Blender QA where applicable, Unreal import validation, DataTable reload/import counts, material/texture binding proof, and staged build proof if playable content is affected. |
| Lifecycle coordination | Run lifecycle, loaded run, run end, return to frontend, world transition, durable-state flush, teardown audit, runtime drain, or coordinating/overseer systems | Start with `LifecycleSystem/LIFECYCLE_SYSTEM_AGENTS.md` and `LifecycleSystem/LIFECYCLE_COORDINATOR_REGISTRY.md`. Keep `ShutdownSystem` as the quit/pre-exit owner. Prefer lightweight owner-local boundaries first. | Lifecycle registry/audit evidence; focused compile for runtime C++ boundary changes; staged standalone validation when playable standalone behavior changes. |
| Runtime health readiness | Runtime health, startup health, required subsystem availability, diagnostics readiness, PerformanceSystem artifact proof, packaged runtime health, runtime ownership inventory, or shared runtime gate | Start with `PerformanceSystem/PERFORMANCE_SYSTEM_AGENTS.md`, `PerformanceSystem/RUNTIME_HEALTH_GATE.md`, and `PerformanceSystem/RUNTIME_OWNERSHIP_INVENTORY.md`. Use `Scripts/RunRuntimeHealthGate.ps1` for packaged startup/runtime diagnostics proof. Do not replace full staged-readiness or pre-release smoke suites with this gate. | `Saved/RuntimeHealthGate/<timestamp>/summary.json`, runtime launch log/screenshot, child staged-readiness summary, fresh PerformanceSystem snapshot/session summary, and schema/write-queue assertions. |
| Staged standalone verification | Any change affecting the playable standalone build or taskbar shortcut | Run `Scripts/StageStandaloneBuild.ps1` to refresh the staged standalone and shortcut. Do not treat source/editor compile as proof of what the taskbar launches. Use `Scripts/RunStagedBuildReadinessGate.ps1` only when app-booting smoke proof is explicitly requested. | Refreshed staged exe at `Saved/StagedBuilds/Windows/T66/Binaries/Win64/T66.exe`, verified shortcut target, and smoke logs only when requested. |
| Video generation | Frontend/hero-selection generated videos or existing video-generation workflow research | Start from `Video Generation` docs, manifests, job records, and validators. Do not jump straight to ad hoc ffmpeg or generation scripts. | Manifest/job counts, runtime movie paths, validator output, and encoded media evidence. |
| Data asset import/reload | Source CSV/JSON/PNG changes that back Unreal DataTables or cooked assets | Update source data, then run the owning Unreal commandlet/import script. Do not stop at file edits when runtime assets must be refreshed. | Script log markers such as DataTable reload/import counts and `QUIT_EDITOR requested`. |
| Performance and optimization | Performance, profiling, diagnostics, telemetry, perception, or optimization-readiness | Start with `PerformanceSystem/PERFORMANCE_SYSTEM_AGENTS.md`; keep contracts under `PerformanceSystem/` and runtime code under `Source/T66/PerformanceSystem/`. Use runtime health readiness when packaged diagnostics proof is needed. | PerformanceSystem outputs, logs, runtime health gate output, or explicit skipped-verification note. |
