# T66 Full Audit — 2026-05-04

Read-only audit of `c:\UE\T66` (Unreal Engine 5.7, multi-module: T66, T66Mini, T66TD, T66Idle, T66Deck, T66Editor) covering three concerns:

1. Things that hurt performance on low-end PCs
2. Things that should be data-driven but currently aren't
3. Things that could cause crashes

Severity scale: **CRITICAL / HIGH / MEDIUM / LOW**.

## 1. Performance — things that will hurt low-end PCs

### 1a. Per-frame Tick work that scales with actor count

- **HIGH** — `Source\T66\Gameplay\T66EnemyBase.cpp:892-1143` — every live enemy ticks and calls `T66ResolveClosestPlayerPawn` (936-940), which iterates all PlayerControllers (172-199). Cost is `O(enemies × players)` every frame. Cache nearest-player on the GameMode/subsystem and refresh on a 5–10 Hz timer.
- **HIGH** — `Source\T66\UI\HUD\T66GameplayHUDWidget.cpp:51-195` — `NativeTick` runs `RefreshSpeedRunTimers`, throttled DPS, `PresentationController.Tick`, and during attack-lock writes crosshair transform every frame (107-124) plus `FString::Printf → SetText` (141-162). Drive crosshair from PC events; only call `SetText` when the displayed value actually changes.
- **MEDIUM** — `Source\T66Mini\Private\Gameplay\T66MiniEnemyBase.cpp:218-329` — same "find nearest pawn" per Mini enemy per frame (260, 411-417). Same fix.
- **MEDIUM** — `Source\T66\Gameplay\T66HeroBase.cpp:580-758` — hero `Tick` does ground line traces (611-661), animation-state evaluation with `PlayAnimation` (699-731), and cooldown bar UMG updates (737-758).
- **MEDIUM** — `Source\T66\Gameplay\T66HeroProjectile.cpp:68-102` — homing projectiles tick + rewrite velocity each frame. Use `ProjectileMovement` homing where possible and pool projectiles.
- **MEDIUM** — `Source\T66\Gameplay\T66GameMode.cpp:1125-1201` — non-tower path runs `MaintainPlayerTerrainSafety()` every frame (1137-1140) while tower uses a 0.1s accumulator. Throttle non-tower the same way.
- **MEDIUM** — `Source\T66\Gameplay\T66EnemyBase.cpp:897` — every enemy constructs an `FLagScopedScope` (`T66LagTrackerSubsystem.h:92-127`). Gate construction behind `IsEnabled()` first.
- **MEDIUM** — `Source\T66\Gameplay\Traps\T66FloorSpikePatchTrap.cpp:299-350` — during warning/rise, updates all spike instance transforms each tick (341-349, plus `MarkRenderStateDirty` 459-491). Warning phase also spawns ~12 Niagara pixels every ~0.08s (312-337).
- **MEDIUM** — `Source\T66\UI\T66VendorOverlayWidget.cpp:1942, 1960-1979` — 30 Hz timer calling `SetWidthOverride` triggers a Slate layout pass each tick. Drop to 10–15 Hz.
- **MEDIUM** — `Source\T66\UI\Components\T66LeaderboardFilterButton.cpp:77-145` — `NativeTick` drives a sprite's MID scalar every frame. Use a brush animation or sprite-FPS timer.
- **MEDIUM** — `Source\T66\UI\Gambler\T66GamblerOverlayWidget_Cheat.cpp:271, 379` — ~30 Hz coin spin timer; same critique.
- **MEDIUM** — `Source\T66Idle\Private\UI\Screens\T66IdleMainMenuScreen.cpp:165-172, 788-817` — idle simulation runs every frame from a UMG screen tick.
- **LOW** — `Source\T66\UI\T66QuickArcadeWidget.cpp:309`, `T66GoldMinerArcadeWidget.cpp:350`, `T66WhackAMoleArcadeWidget.cpp:351`, `T66TopwarArcadeWidget.cpp:371` — 0.04–0.05s repeating timers in arcade minigames.
- **LOW** — `Source\T66\Gameplay\T66EnemyBase.cpp:938-939` — `UE_LOG(*GetName())` in tick path.

## 3. Crash risks

### 3.1. HTTP / async lifetime

- **HIGH** — `Source\T66\Core\T66WebImageCache.cpp:58` — `Request->OnProcessRequestComplete().BindLambda([this, CapturedUrl](...){ OnDownloadComplete(...); })`. Raw `this` capture on HTTP completion. Use-after-free if subsystem torn down. Fix with `TWeakObjectPtr` / `CreateWeakLambda` (the file already uses that pattern at `T66UITexturePoolSubsystem.cpp:147`).
- **HIGH** — `Source\T66\Core\T66WebImageCache.cpp:79` — `AsyncTask(ENamedThreads::GameThread, [this, Url, Data, bSuccess](){ … CachedTextures.Add … OnWebImageReady.Broadcast });`. Same issue on game-thread continuation.
- **HIGH** — `Source\T66\UI\T66SlateTextureHelpers.cpp:94` — `Pool->RequestTexture(..., [&Brush](UTexture2D* Loaded){ Brush.SetResourceObject(Loaded); })`. Captures `Brush` by reference; if any caller passes a stack-local brush the async write hits freed memory.
- **MEDIUM** — `Source\T66\Core\T66UITexturePoolSubsystem.cpp:221` — waiters with `bHasRequester == false` invoke their `TFunction` ungated.
- **LOW** — `Source\T66Mini\Private\Core\T66MiniLeaderboardSubsystem.cpp:77` — `Deinitialize() { delete SteamBridge; SteamBridge = nullptr; }` without explicit cancel/drain.

Backend HTTP path is mostly safe — `T66BackendAccountApi.cpp:15` and friends use `BindUObject(this, …)`.

### 3.2. Network JSON parsing

These crash (or `ensure`/`check` depending on engine build) if the backend returns a body without expected shape (outage page, partial response, schema bump):

- **HIGH** — `Source\T66\Core\Backend\T66BackendLeaderboardApi.cpp:312-314, 485, 497-553` — multiple `Json->GetNumberField` / `GetStringField` / `GetBoolField` for `rank`, `total_entries`, and per-entry fields with no `HasField` or `TryGet*` guard.
- **HIGH** — `Source\T66\Core\Backend\T66BackendAccountApi.cpp:41` — `Json->GetStringField(TEXT("restriction"))` with no guard.
- **HIGH** — `Source\T66\Core\Backend\T66BackendRunApi.cpp:447` — `Json->GetStringField(TEXT("status"))`.
- **HIGH** — `Source\T66\Core\Backend\T66BackendRunSummaryParser.cpp:29-36` — `hero_id`, `companion_id`, `display_name` read without the `HasField ? ...` guard that lines 18-27 in the same function use.

Fix uniformly: `TryGetStringField` / `TryGetNumberField` everywhere, with explicit defaults.

### 3.3. Save load casts

- **MEDIUM** — `Source\T66\Core\T66SaveSubsystem.cpp:124-126` — `Cast<UT66RunSaveGame>(Loaded)`. Returns `nullptr` for wrong class / corrupted slot. Crash is downstream-caller dependent.
- **LOW** — `Source\T66\Core\T66SaveMigration.h` — pure `FName` remap, no pointer or index work. Risk is logical only.
- **GOOD** — no `CastChecked<>` matches anywhere in `Source/`.

### 3.4. UObject lifetime / delegate teardown

- **MEDIUM** — `Source\T66\Core\T66LeaderboardSubsystem.cpp:131-139` — `Backend->OnAccountStatusComplete.AddDynamic(this, …)` with no matching `RemoveDynamic` / `RemoveAll` in `Deinitialize`.
- **GOOD** — `Source\T66\UI\HUD\T66GameplayHUDWidget.cpp:324-382` properly clears timers and removes delegates in destruct paths.

### 3.5. `check()` macros that abort the game in dev

- **MEDIUM** — `Source\T66\UI\HUD\T66GameplayHUDWidget.cpp:46` — `const FT66HUDPresentationController& GetPresentationController() const { check(PresentationController); … }`.

### 3.6. Misc

- **LOW** — `Source\T66\Core\Backend\T66BackendSubsystem.cpp:210` — `GConfig->GetString(...)` without `if (GConfig)`.
- **LOW** — `Source\T66\Gameplay\T66CombatComponent.cpp:435` — `reinterpret_cast<UPTRINT>(TargetActor)` used as opaque numeric key. Safe in practice.
- Container access: spot checks at `T66TDBattleScreen.cpp:511-518`, `T66SessionSubsystem.cpp:2190`, `T66MiniGameMode.cpp:955` all guard `Num()` before `[0]`. Good hygiene.

## Appendix A — Behavior-preserving line reduction (2026-05-04)

A second pass after the audit consolidated several large duplicated patterns. **No behavior changed** — only the shape of the code. Per-site notes:

### A.1. Shared CSV utility
- **New**: `Source/T66/Core/T66CsvUtil.h` — header-only (`inline`) helpers in namespace `T66CsvUtil`: `TrimCell`, `ParseCsv`, `LoadCsvRows` (with optional `LogContext` to preserve the existing per-module Warning), `GetValue`, `ToInt`, `ToFloat`, `ToDouble`, `ToBool`, `ToName`, `ToColor`, `SplitNameList`, `ProjectContentPath`.
- **Removed** (replaced with thin `FORCEINLINE` forwarders that keep call-site identifiers):
  - `Source/T66Deck/Private/Core/T66DeckDataSubsystem.cpp` — full CSV helper block.
  - `Source/T66Idle/Private/Core/T66IdleDataSubsystem.cpp` — full CSV helper block.
  - `Source/T66TD/Private/Core/T66TDDataSubsystem.cpp` — full CSV helper block.
  - `Source/T66Mini/Private/Core/T66MiniDataSubsystem.cpp` — full CSV helper block.
- Behavior: identical. Mini/TD previously did not log on file-load failure; the consolidated `LoadCsvRows` only logs when an explicit `LogContext` is passed, so Mini and TD still skip the warning.

### A.2. `Find*` predicates in DataSubsystems
Collapsed the 9 (Deck) / 9 (Idle) / 9 (TD) `FindByPredicate` lookups from 4–5-line bodies to single-line definitions. Identical lambdas — only the line layout changed. Files:
- `T66DeckDataSubsystem.cpp`, `T66IdleDataSubsystem.cpp`, `T66TDDataSubsystem.cpp`.

### A.3. `Get*DataTable()` and `Get*Data()` accessors in `T66GameInstance`
- **Added** (`T66GameInstance.h`): private `ResolveCachedDataTable(TObjectPtr<UDataTable>&, const TSoftObjectPtr<UDataTable>&)` and a private `static template` `FindDataRow(...)`.
- **Replaced** in `T66GameInstance.cpp`: 11 × `Get*DataTable()` (Hero / Companion / Idols / Weapons / Items / Bosses / Stages / HouseNPCs / LoanShark / CharacterVisuals / ArcadeInteractables) — each ~14-line body now a one-line forwarder.
- **Replaced**: 8 × simple row accessors (Hero / Companion / Idol / Weapon / Boss / Stage / HouseNPC / LoanShark) → one-line `FindDataRow(...)` calls.
- **Compacted**: `GetAllHeroIDs` and `GetAllCompanionIDs` from 8-line bodies to 2-line bodies.
- Preserved precisely: `GetItemData` (synthetic-item path, primary-stat-type rewriting), `GetArcadeInteractableData` (ArcadeID fallback) — untouched.

### A.4. Profile clamp pattern in `T66MiniSaveSubsystem.cpp`
- 7 × 5-line `const Clamped… ; if (...) { ... ; bChanged = true; }` blocks plus a `for` loop replaced by a single local `ClampField` lambda and 7 one-line calls. Same min thresholds, same `bChanged` semantics.

### A.5. Cached-asset priming
- `T66PlayerController.cpp` (`PrimeGameplayPresentationAssetsAsync`, `HandleGameplayPresentationAssetsLoaded`), `T66CombatComponent.cpp` (mirror), `T66CombatVFX.cpp::WarmupVFXSystems` — collapsed `if (!CachedX) { CachedX = X.Get(); }` 4-line blocks to single lines. Pure formatting; no behavioral change.

### A.6. Why this is safe
- All consolidated helpers are pure functions. None observe or mutate any state outside their parameters.
- The `FORCEINLINE` forwarders keep every call-site identifier (e.g. `T66DeckLoadCsvRows`) bound to the same callable signature it had before.
- The `T66CsvUtil::LoadCsvRows` only logs when given a context name — Deck and Idle previously logged unconditionally, so they still pass `TEXT("T66DeckDataSubsystem")` / `TEXT("T66IdleDataSubsystem")`. Mini / TD previously did not log and still don't.
- The clamp lambda in `T66MiniSaveSubsystem` reads/writes the same fields with the same min thresholds.
