# Current Mob System Architecture and Inventory Investigation

Read-only investigation for the main T66 tower/combat enemy system. Paths are relative to `C:\UE\T66`. The authored main-game combat roster is driven by `DT_Enemies`, `DT_Bosses`, `DT_Stages`, `DT_BossEncounters`, `DT_BossEncounterMembers`, `DT_StatusEffects`, and `DT_CharacterVisuals`, which are configured in `UT66GameInstance` (`Source/T66/Core/T66GameInstance.cpp:202-210`, `Source/T66/Core/T66GameInstance.cpp:879-887`). Separate enemy datasets also exist for Mini, Deck, Idle, and TD modules; those are listed under adjacent enemy-data assets and are not referenced by `AT66EnemyDirector` or `AT66BossBase` in the main tower/combat flow (`Content/Mini/Data/T66Mini_Enemies.csv:1`, `Content/Deck/Data/T66Deck_Enemies.csv:1`, `Content/Idle/Data/T66Idle_Enemies.csv:1`, `Content/TD/Data/T66TD_EnemyArchetypes.csv:1`, `Source/T66/Gameplay/T66EnemyDirector.cpp:38-99`).

### Family Groupings

The main regular mobs use all three grouping mechanisms: class inheritance (`AT66MeleeEnemy`, `AT66RangedEnemy`, `AT66RushEnemy`, `AT66FlyingEnemy`), data fields (`FamilyID`, `RoleID`), and naming/theme conventions (`Dungeon_*`, `Forest_*`, `Ocean_*`, `Martian_*`, `Hell_*`). The `ET66EnemyFamily` enum has `Melee`, `Ranged`, `Rush`, `Flying`, and `Special`, and the director first resolves class from `FT66EnemyData.FamilyID`; the older resolver remains as a fallback based on mob ID strings (`Source/T66/Gameplay/Enemies/T66EnemyFamilyTypes.h:9-16`, `Source/T66/Gameplay/T66EnemyDirector.cpp:61-99`, `Source/T66/Gameplay/Enemies/T66EnemyFamilyResolver.cpp:21-88`, `Content/Data/Enemies.csv:1-26`).

Bosses use `BossPartProfile` values `HumanoidBalanced`, `Sharpshooter`, `Juggernaut`, and `Duelist` from `FBossData`; these profiles configure both hit-zone part layouts and `ET66BossAttackProfile` values. `ET66BossAttackProfile` also has a `Gambler` value used by `AT66GamblerBoss` (`Source/T66/Data/T66DataTypes.h:1138-1146`, `Source/T66/Gameplay/T66BossAttackTypes.h:9-16`, `Source/T66/Gameplay/T66BossBase.cpp:266-339`, `Source/T66/Gameplay/T66GamblerBoss.cpp:28`).

## 4. Spawn System And Stage Relationship

Regular mobs are assigned to stages through `FStageData.EnemyA` through `EnemyE`. The director reads current stage data, falls back to `Mob_Stage%02d_A` through `Mob_Stage%02d_E` only if stage data is missing/empty, then selects a random mob ID from those five slots for both initial tower floor population and runtime trickle waves (`Source/T66/Data/T66DataTypes.h:1446-1460`, `Source/T66/Gameplay/T66EnemyDirector.cpp:38-59`, `Source/T66/Gameplay/T66EnemyDirector.cpp:218-302`, `Source/T66/Gameplay/T66EnemyDirector.cpp:1096-1117`).

Spawn budgets are difficulty/player-experience driven. In current `PlayerExperience.json`, all five difficulty rows set `GameplayFloorsPerStage=3`, `InitialEnemiesPerGameplayFloor=4`, `RuntimeEnemiesPerWave=10`, `RuntimeMaxAliveEnemies=30`, `RuntimeSpawnIntervalSeconds=5.0`, `RuntimeWaveStaggerDurationSeconds=5.0`, and `RuntimeMaxSpawnsPerStaggeredBatch=1` (`Content/Data/PlayerExperience.json:41-53`, `Content/Data/PlayerExperience.json:94-106`, `Content/Data/PlayerExperience.json:147-159`, `Content/Data/PlayerExperience.json:200-212`, `Content/Data/PlayerExperience.json:253-265`). The runtime director clamps and applies these budgets when a tower floor is activated and when runtime trickle waves are scheduled (`Source/T66/Gameplay/T66EnemyDirector.cpp:173-330`, `Source/T66/Gameplay/T66EnemyDirector.cpp:528-620`, `Source/T66/Gameplay/T66EnemyDirector.cpp:1128-1285`).

Bosses are stage-owned through `FStageData.BossID` and `BossEncounterID`. Boss flow resolves stage data, reads encounter members when present, loads each `FBossData` row, honors an optional `BossClass` override, and spawns the primary plus extra encounter members (`Source/T66/Gameplay/GameMode/T66GameMode_BossFlow.cpp:718-741`, `Source/T66/Gameplay/GameMode/T66GameMode_BossFlow.cpp:761-825`, `Source/T66/Gameplay/GameMode/T66GameMode_BossFlow.cpp:827-950`). Boss-only finale stages are flagged in `Stages.csv`, but the tower enemy-director skip path checks the tower layout plus `IsBossRushFinaleStage()` before disabling normal enemy spawns (`Content/Data/Stages.csv:5`, `Content/Data/Stages.csv:9`, `Content/Data/Stages.csv:13`, `Content/Data/Stages.csv:17`, `Content/Data/Stages.csv:21`, `Source/T66/Gameplay/GameMode/T66GameMode_Bootstrap.cpp:662-675`).

## 5. Stats System

Regular mob authored rows do not contain HP, contact damage, movement speed, attack speed, score, XP, or loot fields; they contain identity, grouping, status-effect metadata, and art pipeline fields (`Content/Data/Enemies.csv:1`, `Source/T66/Data/T66DataTypes.h:1230-1277`). Base enemy C++ owns default `MaxHP`, `TouchDamageHearts`, `PointValue`, `XPValue`, and drop-related fields, while subclass constructors own family speed defaults (`Source/T66/Gameplay/T66EnemyBase.h:25-36`, `Source/T66/Gameplay/T66EnemyBase.h:79-110`, `Source/T66/Gameplay/Enemies/T66MeleeEnemy.cpp:7-14`, `Source/T66/Gameplay/Enemies/T66RangedEnemy.cpp:11-18`, `Source/T66/Gameplay/Enemies/T66RushEnemy.cpp:7-13`, `Source/T66/Gameplay/Enemies/T66FlyingEnemy.cpp:7-14`).

At spawn, the director applies stage scaling, difficulty scalar, progression scalar, finale scalar, optional miniboss multipliers, and score freezing/registering (`Source/T66/Gameplay/T66EnemyDirector.cpp:303-310`, `Source/T66/Gameplay/T66EnemyDirector.cpp:1232-1248`). `AT66EnemyBase::ApplyStageScaling` computes base HP as `round(50 * pow(1.1, Stage - 1))` and armor as `0.1 * Multiplier`; `RebuildScaledCombatStats` then applies difficulty/progression/finale/daily/miniboss multipliers to HP and touch damage fields (`Source/T66/Gameplay/T66EnemyBase.cpp:597-681`). The current contact-damage overlap path applies a fixed `DamageHP = 20` through run state, independent of the scaled `TouchDamageHearts` field (`Source/T66/Gameplay/T66EnemyBase.cpp:1127-1149`).

Boss stats live in `Bosses.csv` and `FBossData`, and `AT66BossBase::InitializeBoss` applies boss row values for ID, HP, awaken distance, fire interval, projectile speed, projectile damage hearts, point value, move speed, color, visuals, part profile, attack profile, and current run difficulty (`Content/Data/Bosses.csv:1-24`, `Source/T66/Data/T66DataTypes.h:1148-1228`, `Source/T66/Gameplay/T66BossBase.cpp:688-767`).

## 6. Mob / Elite / Boss Distinctions

The main authored table categories are regular mobs and bosses. Regular mobs are `Enemies.csv` rows spawned through `AT66EnemyDirector` using stage `EnemyA`-`EnemyE` slots and `MobID`; bosses are `Bosses.csv` rows spawned by boss flow using `BossID`, `BossEncounterID`, and optional encounter members (`Content/Data/Enemies.csv:1-26`, `Content/Data/Bosses.csv:1-24`, `Content/Data/Stages.csv:1-21`, `Source/T66/Gameplay/T66EnemyDirector.cpp:38-99`, `Source/T66/Gameplay/GameMode/T66GameMode_BossFlow.cpp:718-950`).

There is no authored `Elite` category field in `Enemies.csv`, `Bosses.csv`, or `Stages.csv`. The current elite-like distinction is a runtime miniboss variant: the director can mark one regular mob slot as miniboss based on `MiniBossChancePerWave`, and the spawned enemy stores `bIsMiniBoss` plus HP/damage/scale multipliers; miniboss deaths also skew loot rarity upward (`Content/Data/Enemies.csv:1`, `Content/Data/Bosses.csv:1`, `Content/Data/Stages.csv:1`, `Source/T66/Gameplay/T66EnemyDirector.cpp:777-815`, `Source/T66/Gameplay/T66EnemyDirector.cpp:1238-1241`, `Source/T66/Gameplay/T66EnemyBase.h:191-201`, `Source/T66/Gameplay/T66EnemyBase.cpp:635-640`, `Source/T66/Gameplay/T66EnemyBase.cpp:1505-1510`).
