### B.2 - Texture binding path

Runtime visual assignment path for imported static enemy visuals:

1. Enemy IDs become visual IDs in `AT66EnemyBase::ConfigureAsMob`: `CharacterVisualID = MobID`; pooled actors reapply visuals immediately if BeginPlay has already run. Evidence: `Source/T66/Gameplay/T66EnemyBase.cpp:393-443`.
2. On normal BeginPlay/setup, enemies call `Visuals->HasCharacterVisual(CharacterVisualID) && Visuals->ApplyCharacterVisual(CharacterVisualID, GetMesh(), VisualMesh, true, false, false, VisualMesh)`. Evidence: `Source/T66/Gameplay/T66EnemyBase.cpp:551-560`.
3. Stage entry preloads the stage enemy and boss visual IDs through `UT66CharacterVisualSubsystem::PreloadCharacterVisual`. Evidence: `Source/T66/Gameplay/GameMode/T66GameMode_Bootstrap.cpp:540-578`.
4. `UT66CharacterVisualSubsystem::ResolveVisual` reads `/Game/Data/DT_CharacterVisuals`, resolves the row by visual ID, and loads either `SkeletalMesh` or `StaticMesh`. Evidence: `Source/T66/Core/T66CharacterVisualSubsystem.cpp:26`, `:787-960`.
5. For the QuadRetro static-mesh path, `ApplyCharacterVisual` clears override materials, sets the resolved static mesh, applies row transform/grounding, hides the skeletal mesh/placeholder, and returns. It does not create a dynamic material or bind a texture at runtime for the static mesh path. Evidence: `Source/T66/Core/T66CharacterVisualSubsystem.cpp:1086-1154`.
6. `Content/Data/CharacterVisuals.csv` rows for the sampled enemies point to static mesh assets only, not texture assets. Evidence: `Content/Data/CharacterVisuals.csv:112-118`.

Texture reference carrier finding: for current QuadRetro static enemy meshes, the MI assigned to the static mesh is the runtime carrier of the texture reference. The data table carries the static mesh path, not the texture path. Import-time scripts do independently locate the pixelated texture and write it into material instance texture parameters: `_find_imported_pixelated_texture` and `_bind_imported_texture_to_materials` in `Scripts/ImportQuadRetroEnemyVisuals.py:82-124`, then the import pass updates data tables at `Scripts/ImportQuadRetroEnemyVisuals.py:267-308`.

Existing dynamic material path: `T66ApplySafeCharacterMaterialOverrides` creates `UMaterialInstanceDynamic` for imported skeletal/FBX-style materials and sets texture/scalar/vector parameters at runtime. Evidence: `Source/T66/Core/T66CharacterVisualSubsystem.cpp:401-480`; this path is called after skeletal mesh assignment at `Source/T66/Core/T66CharacterVisualSubsystem.cpp:1210-1211`. The static QuadRetro enemy branch returns before that call.
